## 1. 背景与目标

### 1.1 背景

用户希望在 `C:\Users\tzy88\Desktop\Yue Agent` 从零搭建一个类似 Codex 桌面端的本地 AI Agent harness（下称 "Yue Agent"）。当前目录为空，只有空的 `doc/` 文件夹。

核心诉求：

- **桌面形态**：目标是桌面智能体应用；前端框架（Tauri / Electron）暂未决定，因此后端必须与 UI 解耦。
- **Python 核心**：编排层使用 Python + LangChain + LangGraph。
- **编码 + 知识库并重**：既能读写代码、执行命令，也能导入文档做本地 RAG。
- **本地优先**：会话记忆、长期记忆、向量数据全部本地存储，不依赖云端服务。
- **多模型可配置**：推理/聊天模型、多模态视觉模型、embedding 模型均可自定义，走 OpenAI 兼容接口。
- **多工作区 + 多会话**：可同时打开多个项目目录，会话可并行运行。
- **尽量完整的第一版**：不是玩具 demo，但也不过度设计。

### 1.2 目标

构建一个**可本地运行、可被任意桌面前端调用**的 Agent 后端：

1. 完整的 Agent 对话循环，支持流式输出、工具调用、中断恢复。
2. 会话持久化与恢复；跨会话长期记忆；上下文自动压缩。
3. 工作区文件读写、代码搜索、命令执行（带审批）、Git 查询。
4. 本地知识库：文档导入、切分、embedding、Chroma 持久化、语义检索。
5. 多模型配置中心：多 provider、多角色模型、密钥安全存储、连通性测试。
6. UI 无关的 HTTP + WebSocket 协议，附带 CLI 客户端用于端到端验证。
7. 为后续 Tauri / Electron 打包预留清晰的接入方式。

### 1.3 非目标（v1 不做）

- 不做联网搜索或网页抓取（按用户要求）。
- 不做云端多租户、账号体系、远程访问。
- 不做前端界面（仅定义协议 + CLI）。
- 不做多智能体协同编排（预留扩展点，v1 单 Agent）。
- 不做 Windows 系统级强沙箱（以"审批 + 路径限制"代替）。
- 不做模型训练/微调。

## 2. 总体架构

### 2.1 分层

```text
┌─────────────────────────────────────────────────────────────┐
│  前端（暂缓）  Tauri (WebView) / Electron / 浏览器           │
│  未来直接消费本地 HTTP + WebSocket 协议                       │
└───────────────────────────┬─────────────────────────────────┘
                            │ 127.0.0.1 + bearer token
┌───────────────────────────▼─────────────────────────────────┐
│  接入层  FastAPI + WebSocket                                  │
│  REST: 会话/文档/设置/模型/审批   WS: 聊天事件流               │
├─────────────────────────────────────────────────────────────┤
│  编排层  LangGraph StateGraph                                 │
│  上下文组装 → 模型调用 → 工具执行 → 审批中断 → 压缩/记忆抽取   │
├──────────────┬──────────────┬──────────────┬────────────────┤
│  工具系统     │  RAG 流水线   │  记忆系统     │  模型路由       │
│  fs/shell/   │  loader/     │  checkpointer│  chat/vision/  │
│  git/rag/    │  splitter/   │  store/      │  embedding     │
│  memory      │  retriever   │  extractor   │                │
├──────────────┴──────────────┴──────────────┴────────────────┤
│  本地存储                                                     │
│  SQLite（会话/设置/文档/审批日志）                            │
│  Chroma（知识库 + 长期记忆向量）                              │
│  Windows 凭据管理器（API Key）                                │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键架构决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 前后端耦合 | 本地 HTTP/WS 服务，前端独立 | Tauri/Electron 未定，协议先行；也便于 CLI 测试 |
| Agent 编排 | 自绘 LangGraph `StateGraph` | 要精确控制审批中断、上下文预算、事件映射；`create_agent` 的中间件机制保留作参考/后续复用 |
| 会话持久化 | LangGraph `SqliteSaver` 为事实源 | 天然支持 checkpoint、恢复、interrupt/resume |
| 消息投影 | 额外 `messages` 投影表 | 前端列表、全文检索、统计需要；由后端幂等写入 |
| 长期记忆 | 自建 `memories` 表 + Chroma 语义索引 | 行为透明、便于去重与作用域管理；不绑定 BaseStore 实现细节 |
| 向量库 | Chroma `PersistentClient` | 零服务、本地持久化、元数据过滤完善 |
| 模型接入 | `ChatOpenAI` + 自定义 base_url | 兼容 DeepSeek/Kimi/通义/vLLM 等 |
| 密钥 | `keyring`（Windows Credential Manager） | 不落明文配置文件 |
| 进程模型 | 单进程 FastAPI + 并发 asyncio 任务 | 避免 SQLite/Chroma 多进程并发问题；会话级串行、跨会话并行 |
| 并发控制 | SQLite WAL + 全局写锁；最大并行 run 数可配置 | 多工作区多会话同时运行，写入安全 |

## 3. 技术选型

### 3.1 运行环境

本机已具备：Python 3.13.9、uv 0.11.26、Node 24、Rust 1.96（Tauri 可用）、约 62GB 可用磁盘。

- Python **3.13**（`uv` 创建项目虚拟环境并锁定版本；若某个依赖暂不兼容 3.13，回退到 3.12）
- 包管理：**uv**（`pyproject.toml` + `uv.lock`）
- 进程：单进程 uvicorn；重任务用 asyncio 后台任务 + 有界队列
- 前端（后续）：Tauri 或 Electron 均有本机工具链基础

### 3.2 依赖清单（核心）

| 类别 | 依赖 | 说明 |
|---|---|---|
| Web | `fastapi`, `uvicorn[standard]`, `websockets` | REST + WS |
| 配置 | `pydantic`, `pydantic-settings` | 配置校验 |
| 编排 | `langgraph`, `langchain`, `langchain-core` | 1.x 系列 |
| 模型 | `langchain-openai` | OpenAI 兼容 |
| 向量 | `chromadb` | 本地持久化 |
| 文档 | `pypdf`, `python-docx`, `unstructured`（可选） | PDF/DOCX；文本/Markdown 原生 |
| 本地 embedding | `sentence-transformers`（可选 extra） | 可选，默认走 API embedding |
| 分词 | `tiktoken` + `tokenizers` | token 预算估算 |
| 安全 | `keyring` | 凭据管理 |
| 路径 | `platformdirs` | 跨平台数据目录 |
| 日志 | `structlog` 或标准 logging + JSON 格式化 | 结构化、脱敏 |
| 测试 | `pytest`, `pytest-asyncio`, `httpx` | 单元 + 集成 |
| 打包 | `pyinstaller`（M6） | Tauri/Electron sidecar |

> 版本策略：首次实现时锁定当前稳定大版本（LangChain/LangGraph 1.x、Chroma 1.x），`uv.lock` 固定；升级单独走回归测试。

### 3.3 前端决策（暂缓，但需预留）

- **Tauri**：体积小、内存占用低，Rust 壳 + WebView；Python 后端打成 sidecar 可执行文件，由 Tauri 启动/守护。
- **Electron**：生态成熟、Node 集成方便，但体积大。
- 两者都只需要：启动本地后端 → 读取端口与 token → 连接 WS。方案书在 M6 提供 `sidecar` 打包说明与握手文件协议，不在 v1 绑定。

## 5. Agent 运行时设计

### 5.1 状态定义（`AgentState`）

```python
class AgentState(TypedDict):
    messages: Annotated[list[AnyMessage], add_messages]
    session_id: str
    workspace: str
    model_profile: str
    attachments: list[Attachment]        # 图片等
    context_budget: ContextBudget        # 各段 token 配额
    retrieved: list[RetrievedChunk]      # 本轮 RAG
    memories: list[MemoryItem]           # 本轮召回
    pending_approval: ApprovalRequest | None
    compressed_summary: str | None
    turn_index: int
```

### 5.2 图结构

```text
START
  │
  ▼
prepare_context ──► llm ──(有 tool_calls)──► approval_gate ──► tools ──┐
  ▲                                             │  (ask)              │
  │                                             ▼                     │
  │                                        interrupt()                │
  │                                             │ resume              │
  │                                             ▼                     │
  │                                          tools ───────────────────┘
  │
  └──(无 tool_calls)──► post_turn ──► END
                            ├─ 记忆抽取
                            ├─ 消息投影
                            └─ 压缩检查（必要时下一轮 prepare 执行）
```

**节点职责：**

| 节点 | 职责 |
|---|---|
| `prepare_context` | 加载工作区规则（`YUE.md` / `AGENTS.md`）、按预算召回长期记忆与 RAG、必要时压缩旧历史、组装 system prompt |
| `llm` | 按角色选模型（有图片则 vision profile），流式输出 token，记录 usage |
| `approval_gate` | 遍历 tool_calls，按策略判定 allow/ask/deny；ask 时 `interrupt()` 挂起 |
| `tools` | 执行允许的工具调用，结果截断、错误包装；记录审批日志 |
| `post_turn` | 异步触发记忆抽取；写消息投影；统计 token；更新会话时间 |

**关键点：**

- **审批用 LangGraph `interrupt()`**：挂起时通过 WS 发 `approval_requested`；前端回 `approval_response` 后以 `Command(resume=...)` 恢复。要求启用 checkpointer。
- **工具循环**：`llm → approval_gate → tools → llm`，由 `should_continue` 条件边控制，设最大迭代数（默认 25）防死循环。
- **会话内串行**：同一 session 同时只允许一个 run；新消息排队或返回 `run_in_progress`。
- **取消**：`cancel` 事件设置取消标记；工具执行在安全点检查；`interrupt` 挂起时可直接丢弃。
- **恢复**：客户端断线重连后通过 `GET /api/sessions/{id}` 拉取投影消息 + `GET /api/sessions/{id}/state` 获取运行状态，再重新订阅 WS。

### 5.4 并发模型（多工作区 + 多会话）

- **跨会话并行**：不同 session 的 run 可同时执行；默认最大并行数 `max_concurrent_runs = 3`（可配置），超出进入 FIFO 队列并推送 `queued` 事件。
- **会话内串行**：同一 session 的图状态不可并发修改；由 `RunManager` 维护 per-session 锁。
- **存储写入**：
  - SQLite 开启 `WAL`、`busy_timeout=5000`；写操作经过进程内全局 `asyncio.Lock`（写少读多）。
  - Chroma 写入串行化（全局锁），检索可并行；embedding API 调用按 provider 加并发信号量（默认 4）。
  - LangGraph checkpointer 访问通过线程安全封装（单连接 + 锁，或 `aiosqlite`）。
- **资源隔离**：每个 session 持有自己的 workspace 根路径、模型 profile、知识库 collection；记忆按 workspace 作用域隔离。
- **后台任务**：记忆抽取、文档导入、摘要压缩进入有界工作队列（默认 2 个 worker），不阻塞对话主循环。
- **进程单实例**：启动时对 `<YUE_HOME>` 加文件锁，防止两个后端实例同时写同一份数据。

### 5.3 上下文预算

每轮按 token 预算分配（默认，可配置）：

| 区域 | 预算占比 | 说明 |
|---|---|---|
| 系统提示 + 工作区规则 | 10% | 固定，超长截断 |
| 长期记忆 + RAG | 25% | 按相关度排序，去重 |
| 对话历史 | 50% | 最近若干轮原文 |
| 输出预留 | 15% | `max_tokens` 与模型窗口取小 |

- token 计数优先用模型返回的 usage；估算用 `tiktoken`（OpenAI 系）或 `tokenizers`（本地模型），统一留 10% 余量。
- **压缩触发**：历史 token 超过阈值（如模型窗口 70%）时，将最早的部分对话交给 chat 模型摘要，摘要作为 `compressed_summary` 保留，删除对应原文消息（通过自定义 reducer 实现）。
- 摘要提示词要求保留：用户目标、已做决策、未完成事项、关键文件路径、报错信息。

## 6. 数据层设计

### 6.1 目录布局

```text
${YUE_HOME:-%LOCALAPPDATA%\YueAgent}/
├── data.db                 # SQLite 主库
├── checkpoints.db          # LangGraph SqliteSaver
├── chroma/                 # Chroma 持久化目录

```

开发模式默认 `YUE_HOME=<项目>/data`（加入 `.gitignore`）；工作区由用户显式选择。

### 6.2 SQLite 表（主库）

```sql
workspaces(
  id TEXT PRIMARY KEY, name TEXT, root_path TEXT UNIQUE,
  created_at TEXT, last_opened_at TEXT
)

sessions(
  id TEXT PRIMARY KEY, title TEXT, workspace_id TEXT,
  model_profile TEXT, created_at TEXT, updated_at TEXT,
  archived INTEGER DEFAULT 0
)

messages(                     -- 投影表，便于列表/检索/统计
  id TEXT PRIMARY KEY, session_id TEXT, role TEXT,
  content_json TEXT, tool_calls_json TEXT, created_at TEXT,
  token_count INTEGER, run_id TEXT
)
CREATE INDEX idx_messages_session ON messages(session_id, created_at);
-- 可选：FTS5 虚拟表做全文检索

documents(
  id TEXT PRIMARY KEY, workspace_id TEXT, collection TEXT,
  source_path TEXT, sha256 TEXT UNIQUE, title TEXT, mime TEXT,
  size INTEGER, status TEXT, chunk_count INTEGER, error TEXT,
  created_at TEXT, updated_at TEXT
)

memories(
  id TEXT PRIMARY KEY, scope TEXT,        -- global | workspace:<workspace_id>
  kind TEXT,                               -- fact | preference | decision
  content TEXT, importance REAL,
  source_session TEXT, created_at TEXT, updated_at TEXT
)

approvals(
  id TEXT PRIMARY KEY, session_id TEXT, run_id TEXT,
  tool_call_id TEXT, tool_name TEXT, args_json TEXT,
  policy TEXT, decision TEXT, reason TEXT,
  created_at TEXT, decided_at TEXT
)

settings(key TEXT PRIMARY KEY, value_json TEXT, updated_at TEXT)
```

**会话事实源**：LangGraph checkpointer 中的图状态。`messages` 表是幂等投影（按 message id 去重），用于 UI 快速读取和检索，二者不一致时可重建投影。

### 6.3 Chroma 设计

- 目录：`<YUE_HOME>/chroma`
- Collection（按工作区隔离）：
  - `kb_<workspace_id>`：该工作区默认知识库的文档块；metadata：`doc_id`, `workspace_id`, `source`, `chunk_index`, `page`, `heading`, `mime`, `created_at`
  - `memories`：长期记忆语义索引；metadata：`memory_id`, `scope`, `workspace_id`, `kind`
  - 后续支持一个工作区多个知识库时，命名 `kb_<workspace_id>_<kb_id>`
- 每个 collection 的 metadata 记录 `embedding_model`, `dimension`, `chunk_size`, `created_at`；**禁止混用不同 embedding 模型**，更换模型必须新建 collection 并重建索引。
- 写入串行化（单进程 asyncio 锁）；批量 `add`（默认 64 条/批）；失败重试 + 断点续传。

```yaml
    role: embedding
    provider: openai_compatible
    base_url: https://api.siliconflow.cn/v1
    model: BAAI/bge-m3
    api_key_ref: "keyring:yue/model/bge-m3-api"
    dimensions: 1024

  # 可选：完全本地 embedding，需安装 sentence-transformers extra
  # - id: bge-m3-local
  #   role: embedding
  #   provider: local_sentence_transformers
  #   model: BAAI/bge-m3
  #   dimensions: 1024
```

### 7.2 规则

- **角色解析**：`chat`（默认对话与工具调用）、`utility`（摘要压缩、记忆抽取等后台任务，可省略并回退 chat）、`vision`（消息含图片时自动切换或由会话指定）、`embedding`（按 collection 绑定，**默认走 OpenAI 兼容 API**，本地 embedding 作为可选 provider）。可选 `reasoning` 角色（用于复杂规划，v1.1）。
- **能力标记**：`tools` / `vision` / `reasoning` / `streaming`。缺 `tools` 的模型只做纯对话；缺 `vision` 时图片走 OCR 或提示用户切换。
- **密钥**：`keyring` 服务名 `yue-agent`，键名 `model/<profile_id>`；配置文件只存 `api_key_ref`。设置 API 接受密钥写入，读取时永不明文返回（只返回 `已配置/未配置`）。
- **连通性测试**：`POST /api/models/{id}/test` 发一条最小请求，校验鉴权、模型名、工具调用支持。
- **自动回退**：`chat` 模型调用失败时按配置顺序回退到备用 profile，并在事件流中提示。

## 8. 后端 API 与事件协议

### 8.1 通用约定

- 仅监听 `127.0.0.1`；启动生成随机 `token`，所有 REST 与 WS 握手要求 `Authorization: Bearer <token>`。

### 8.3 WebSocket `/ws/chat/{session_id}`

**客户端 → 服务端：**

```json
{ "type": "user_message", "content": "...", "attachments": [{"type":"image","path":"..."}] }
{ "type": "approval_response", "approval_id": "...", "decision": "allow|deny", "reason": "..." }
{ "type": "cancel" }
{ "type": "ping" }
```

**服务端 → 客户端（统一 envelope）：**

```json
{ "v": 1, "seq": 42, "ts": "2026-10-19T12:00:00Z", "type": "...", "data": {} }
```

事件类型：

| type | data | 说明 |
|---|---|---|
| `run_started` | `run_id, turn_index` | 新一轮开始 |
| `token_delta` | `run_id, text` | 流式文本 |
| `message_completed` | `run_id, message_id, usage` | 助手消息完成 |
| `tool_call_started` | `run_id, tool_call_id, name, args` | 工具开始 |

| `approval_requested` | `approval_id, tool_call_id, name, args, risk, policy` | 请求审批 |

| `context_updated` | `retrieved, memories, compressed` | 本轮注入上下文摘要 |

| `error` | `code, message, recoverable` | 错误 |
| `pong` | — | 心跳 |

**断线恢复**：WS 断开不取消 run（默认）；重连后先 REST 拉取状态，再订阅。事件带 `seq`，客户端可检测丢包。

## 9. 工具系统

### 9.1 工具清单（v1）

| 工具 | 参数 | 风险 | 默认策略 |
|---|---|---|---|
| `read_file` | path, offset?, limit? | 低 | allow（工作区内） |
| `write_file` | path, content | 中 | ask（可配置为 allow） |
| `edit_file` | path, old_string, new_string, replace_all? | 中 | ask |
| `list_dir` | path, depth? | 低 | allow |
| `glob` | pattern, path? | 低 | allow |
| `grep` | pattern, path?, glob?, max_results? | 低 | allow |
| `run_command` | command, cwd?, timeout_s? | 高 | ask（白名单命令可 allow） |
| `git_status` | cwd? | 低 | allow（只读） |
| `git_diff` | cwd?, path?, staged? | 低 | allow（只读） |
| `search_knowledge` | query, collection?, top_k? | 低 | allow |
| `remember` | content, kind, scope | 低 | allow |

> 不提供 web 搜索/抓取工具。Git 写操作（commit/push）v1 不提供，只能由 `run_command` 执行且必须审批。

### 9.2 注册与 schema

- 每个工具声明：`name`、`description`、`args_schema`（pydantic）、`risk`、`read_only`、`handler`。
- 由注册表统一导出 OpenAI function-calling JSON schema，保证模型侧一致。
- 工具结果统一包装：`{ ok, content, metadata }`；输出超过 `max_output_chars`（默认 32k）截断并标注。

### 9.3 权限与沙箱

- **策略来源**（优先级从高到低）：单次审批记忆 → 会话级覆盖 → 全局设置 → 默认策略。
- **路径沙箱**：所有文件工具将路径 `resolve()` 后校验是否位于**当前会话所属工作区**的根路径（每个 session 绑定一个 workspace；全局不共享文件权限）；拒绝符号链接逃逸、`..` 越界、系统敏感目录（`C:\Windows`、用户凭据目录）。多工作区并行时，工具执行上下文携带各自的 workspace，互不串权。
- **命令策略**：
  - 默认 `ask`；可按前缀白名单配置 `allow`（如 `git status`、`ls`、`dir`、`python --version`）。
  - 明确拒绝的高危模式（`format`、`shutdown`、删除系统目录等）直接 `deny`。
  - 执行：`subprocess`，显式 `cwd`、超时（默认 120s）、环境变量白名单、输出上限；Windows 下默认经 `cmd.exe /c`（可配置 PowerShell）。
  - **不是系统级沙箱**：文档与 UI 明确提示风险，审批弹窗展示完整命令。
- **审批中断**：`approval_gate` 节点在 `interrupt()` 前写入 `approvals` 表；恢复后记录决策与耗时；支持"本会话记住此选择"。
- **审计**：所有工具调用（含 allow）记录到日志（脱敏），审批记录可查询。

## 10. RAG 与记忆流水线

### 10.1 文档导入

```text
选择文件/目录
  → 计算 sha256（去重）
  → 解析（txt/md/pdf/docx/代码）
  → 文本归一化（去页眉页脚、合并换行）
  → 切分（结构感知）
  → embedding（批量、可取消）
  → 写入 Chroma + documents 表
  → 进度事件
```

- **支持格式**：`.txt`, `.md`, `.pdf`, `.docx`, 常见代码文件（`.py/.js/.ts/.java/.go/.rs/.c/.cpp/.h/.json/.yaml/.toml/.sql` 等）。
- **切分**：`RecursiveCharacterTextSplitter`，按格式选择分隔符（Markdown 标题、代码函数/类边界、段落）；默认 chunk 1000 字符、overlap 150；保留 heading/page 元数据。
- **去重**：同 `sha256` 已存在则跳过或提示覆盖；文件变更后重新导入生成新版本（`doc_id` 不变，块重建）。
- **任务模型**：持久化 job 状态（`documents.status = pending|processing|ready|failed`），单并发 worker，可取消；进度通过 WS `ingest_progress` 或 REST 轮询。
- **规模护栏**：单文件默认上限 50MB、单次导入文件数上限 500、embedding 批次 64；超限提示分批。

### 10.2 检索

- 默认向量检索 `top_k=8`；可选 MMR（`lambda=0.5`）提升多样性。
- 元数据过滤：按 collection、文件类型、路径前缀。
- 结果组装：去重（同 doc 相邻块合并）→ 按分数排序 → 注入上下文时附 `[来源: 文件名#块号]`。
- **引用**：工具返回结构化引用，前端可展示来源；模型被要求在回答中使用来源标记。
- **v1.1 可选**：混合检索（BM25 + 向量 RRF 融合）、reranker（本地 bge-reranker / API）。

### 10.3 记忆

**短时记忆**
- `thread_id = session_id`，`SqliteSaver` 持久化完整图状态。
- 恢复会话时直接续跑；上下文压缩见 5.3。

**长期记忆**
- 写入时机：
  1. 模型显式调用 `remember` 工具；
  2. 回合结束后的 `post_turn` 异步抽取（**默认开启**，设置可关闭）：从本轮对话中提取稳定的用户偏好、项目事实、关键决策。
- 抽取模型：优先使用 `utility` 角色（低成本模型），未配置则回退 `chat`；抽取任务进入后台有界队列，避免阻塞与并发风暴。
- 抽取约束：只存"未来仍有用"的信息；每条一行、自包含；带 `kind` 与 `importance`。同一轮最多写入 5 条。
- 去重/更新：新记忆 embedding 与现有记忆相似度 > 0.92 时合并更新，否则新增；支持用户手动编辑/删除。
- 作用域：`global`（跨项目）/ `workspace:<workspace_id>`（仅当前工作区）。多工作区并行时按各自作用域隔离召回。
- 召回：每轮按当前用户消息做语义检索（top 5）+ 固定置顶记忆；注入前按 token 预算裁剪。

## 11. 安全设计

| 风险 | 措施 |
|---|---|
| 本地端口被其他进程访问 | 仅绑 `127.0.0.1`；Bearer token；握手文件 ACL |
| API Key 泄露 | Windows 凭据管理器；日志/配置/API 响应永不明文回显 |
| 越权文件访问 | 工作区路径白名单 + realpath 校验 + 敏感目录拒绝 |
| 危险命令 | 默认人工审批；高危模式 deny；超时与输出限制 |
| 提示注入（文档/工具输出） | 检索内容标记为不可信数据；系统提示声明；工具权限不因内容改变 |
| 日志泄露 | 结构化日志脱敏（key/token/命令参数中的密钥模式） |
| 依赖供应链 | `uv.lock` 固定版本；定期审计 |

## 13. 风险与待确认事项

| 风险/问题 | 影响 | 建议 |
|---|---|---|
| 模型工具调用能力参差 | 部分 OpenAI 兼容模型 function calling 不稳定 | 能力标记 + 测试按钮 + 失败重试；必要时用 JSON 模式兜底 |
| Windows 无强沙箱 | 命令执行有真实风险 | 默认全审批、超时、工作区限制；高风险模式 deny；文档明确声明 |
| Chroma/SQLite 并发 | 多进程写入可能损坏 | 单进程 + 写锁；禁止多实例同时打开同一 `YUE_HOME`（启动加文件锁） |
| embedding 模型更换 | 旧向量失效 | collection 绑定模型；更换必须重建；UI 提示 |
| API embedding 依赖网络与配额 | 导入/检索失败、成本 | 失败重试与退避；批量 + 并发上限；可选本地 embedding 兜底 |
| 多会话并行资源争用 | 响应变慢、限流 | 最大并行数、provider 信号量、后台任务有界队列 |
| token 计数不精确 | 压缩时机偏差 | 优先 usage，估算留余量；可配置阈值 |
| 长对话成本/延迟 | 体验下降 | 摘要压缩、RAG top_k 限制、可关闭自动记忆抽取 |
| 前端 Tauri vs Electron | 打包方案不同 | 后端协议先冻结；M6 再定；sidecar 方式两者通用 |
| LangChain/LangGraph 版本演进快 | API 变动 | 锁版本 + 关键封装隔离（模型/工具/持久化） |

**已确认的默认值：**
- embedding 默认走 **OpenAI 兼容 API**；本地 `sentence-transformers` 作为可选 extra。
- 回合后自动记忆抽取**默认开启**，使用 `utility` 角色模型，可在设置中关闭。
- 支持**多工作区 + 多会话并行**，会话内串行、跨会话并行，默认最大并行 3。

**仍需后续确认：**
1. 前端最终选 Tauri 还是 Electron（M6 前决定即可）。
2. API embedding 的具体供应商与模型（示例用 SiliconFlow 的 BGE-M3，可随时替换）。
3. 是否需要在 v1 就启用混合检索 / reranker（建议 v1.1）。
